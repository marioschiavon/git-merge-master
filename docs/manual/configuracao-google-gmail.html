Configure o Google Cloud para conectar Gmail no Leaderei

A gente precisa da sua ajuda para fazer uma configuração no Google Cloud Console. Com isso pronto, seus usuários vão conseguir clicar em “Conectar Gmail” dentro do Leaderei e usar o próprio e-mail para enviar e receber mensagens pelo app. Siga os passos abaixo e, no final, nos envie as credenciais de forma segura.

O que você vai fazer

Você vai criar um aplicativo OAuth próprio dentro do Google Cloud da sua conta. Esse aplicativo é quem pede permissão para acessar o Gmail dos seus usuários, mas cada um autoriza individualmente — o Leaderei nunca acessa a conta de ninguém sem consentimento.

Resumindo, é só você:

  1. Criar um projeto no Google Cloud.
  2. Ativar a Gmail API (e a People API, se solicitada).
  3. Configurar a tela de consentimento OAuth.
  4. Criar as credenciais OAuth 2.0 e cadastrar as URLs do app.
  5. Enviar o Client ID e o Client Secret para a gente cadastrar no painel.
🔒

Importante: Client ID e Client Secret são credenciais sensíveis. Não envie por WhatsApp, e-mail aberto ou qualquer canal público. Use apenas o canal seguro combinado com a equipe Leaderei.

Passo a passo no Google Cloud Console

  1. Crie (ou escolha) o projeto

    Acesse console.cloud.google.com com a conta Google que você quer usar como dono do app.

    • No topo da tela, clique no seletor de projetos e depois em Novo projeto.
    • Dê um nome claro, por exemplo: Leaderei - Gmail.
    • Confirme e aguarde a criação.

  2. Ative as APIs necessárias

    Vá em APIs e serviços → Biblioteca e ative:

    • Gmail API — essencial para enviar e ler e-mails.
    • People API — usada para obter nome e e-mail do usuário que autoriza.

  3. Configure a tela de consentimento OAuth

    Vá em APIs e serviços → Tela de consentimento OAuth.

    • Escolha Externo (para que qualquer pessoa com Gmail possa usar).
    • Preencha:
      • Nome do app: Leaderei (ou o nome público do seu app).
      • E-mail de suporte ao usuário: um e-mail ativo e monitorado.
      • Logo: opcional, mas recomendado. Use o logo oficial do app.
      • Domínio do aplicativo: adicione o domínio principal do app, por exemplo app.leaderei.com.br.
      • Link para a política de privacidade e Termos de serviço — precisam estar publicados em URLs públicas.
    • Salve e continue até o final.
    ⚠️

    Sem política de privacidade e termos públicos, o Google rejeita a verificação. Tenha essas páginas no ar antes de submeter o app para análise.

  4. Adicione os escopos (Scopes)

    Ainda na tela de consentimento, em Escopos, adicione todos os escopos abaixo. Eles definem exatamente o que o app pode fazer no Gmail do usuário:

    https://www.googleapis.com/auth/gmail.send
https://www.googleapis.com/auth/gmail.readonly
https://www.googleapis.com/auth/gmail.modify
https://www.googleapis.com/auth/userinfo.email
https://www.googleapis.com/auth/userinfo.profile
openid
    • gmail.send, gmail.readonly e gmail.modify são escopos restritos/sensíveis do Gmail. O Google exige verificação extra para liberá-los.
    • Os escopos userinfo.email, userinfo.profile e openid servem apenas para identificar o usuário (nome e e-mail).

  5. Crie as credenciais OAuth 2.0

    Vá em APIs e serviços → Credenciais → Criar credenciais → ID do cliente OAuth. Escolha Aplicativo da Web.

    Informações gerais

    • Nome: Leaderei Web (pode ser qualquer nome interno).

    Origens JavaScript autorizadas

    Adicione as URLs públicas do app. Se estiver em dúvida, inclua as três:

    https://app.leaderei.com.br
https://leaderei-app.lovable.app
https://id-preview--b5896184-51c5-4d86-ac16-a70f7aac80fb.lovable.app

    URI de redirecionamento autorizado

    Esta é a URL mais importante. O Google redireciona o usuário de volta para o app exatamente nesse endereço após autorizar. Copie sem alterar:

    https://plfcbbqzpcbgykfervnp.supabase.co/functions/v1/email-connect-callback
    💡

    Se aparecer algum erro “redirect_uri_mismatch” no futuro, a causa mais comum é essa URL ter sido copiada com espaço, barra a mais ou a menos.

    Clique em Criar. Você verá um popup com o Client ID e o Client Secret. Anote os dois com segurança.

  6. Publique e submeta para verificação

    Com o app em Modo de teste, apenas 100 usuários podem usar e todos precisam ser adicionados manualmente como “usuários de teste”. Para liberar para todos os seus clientes:

    1. Na tela de consentimento, clique em Publicar aplicativo.
    2. Como os escopos do Gmail são restritos, o Google pedirá uma verificação de segurança.
    3. Preencha o questionário:
      • Explique por que o app precisa de cada escopo (ex.: “enviar e-mails de prospecção em nome do usuário, ler respostas para triagem da IA”).
      • Forneça um vídeo curto demonstrando o fluxo: o usuário clica em “Conectar Gmail”, escolhe a conta, vê a tela de permissão e retorna ao app.
    4. Os escopos gmail.send, gmail.readonly e gmail.modify geralmente exigem uma avaliação de segurança CASA. O Google indica o parceiro e o custo quando aprova a etapa inicial. O prazo costuma ser de 2 a 8 semanas.
    ⚠️

    Não é possível pular a verificação para uso em escala. Enquanto ela não é concluída, o app funciona normalmente em modo de teste com até 100 contas previamente autorizadas.

O que fazer depois de configurado

Envie para a gente, por canal seguro:

  1. O Client ID (começa com números, termina com .apps.googleusercontent.com).
  2. O Client Secret (uma string aleatória de letras e números).
  3. A confirmação de que a tela de consentimento foi publicada ou se ainda está em modo de teste.

Com esses dados, a gente cadastra as credenciais no backend e testa a conexão com uma conta de e-mail de teste.

🔒

Importante: guarde o Client Secret em um cofre de senhas. Se ele vazar, qualquer pessoa pode se passar pelo seu app perante o Google. Se achar que vazou, revogue a credencial imediatamente nas Credenciais do Google Cloud e gere um novo par.

Erros comuns e como evitar

  • “redirect_uri_mismatch” — a URI cadastrada no Google não está exatamente igual à usada pelo app. Verifique barras finais, http vs https e parâmetros.
  • “Acesso bloqueado: o app não foi verificado pelo Google” — normal durante o modo de teste. Adicione o e-mail do teste em Usuários de teste ou conclua a verificação.
  • “Google hasn’t verified this app” com opção “Avançado” — o app ainda não passou pela verificação. Usuários de teste conseguem prosseguir; usuários finais só conseguirão após a verificação.
  • Escopos não aparecem na tela de consentimento — confira se foram salvos na aba Escopos e se não há duplicatas.
  • Domínio do app não aceito — a origem JavaScript deve usar HTTPS e corresponder exatamente ao domínio acessado pelo usuário.

  • Projeto criado no Google Cloud
  • Gmail API e People API ativadas
  • Tela de consentimento preenchida (nome, e-mail, domínio, política de privacidade e termos)
  • Escopos do Gmail e userinfo adicionados
  • Credencial “Aplicativo da Web” criada com as origens e redirect URI corretos
  • Client ID e Client Secret anotados com segurança
  • Aplicativo publicado (ou, se em teste, e-mails de teste adicionados)
